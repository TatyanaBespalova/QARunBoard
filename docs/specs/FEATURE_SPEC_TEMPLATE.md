# Feature Specification

## Goal

Describe the user-visible outcome this change should achieve.

## Context

Describe the current behaviour, relevant product context, and why the change is needed.

## Constraints

List constraints that must be respected.

Examples:

- preserve existing behaviour unless explicitly changed;
- reuse existing project patterns where appropriate;
- do not introduce new dependencies unless required;
- preserve accessibility and responsive behaviour;
- do not invent unspecified product behaviour.

## Acceptance Criteria

Define observable conditions that must be true for the feature to be considered complete.

- [ ] Criterion 1
- [ ] Criterion 2
- [ ] Criterion 3

## Validation Notes

Define any specific validation expected for this feature.

Examples:

- automated tests;
- lint and build;
- browser/manual validation;
- responsive behaviour;
- keyboard accessibility;
- relevant edge cases.

## Open Questions

List unresolved product or technical questions.

If any unresolved question could materially affect behaviour, scope, data, acceptance criteria, architecture, security, dependencies, or an irreversible action, resolve it before implementation.
