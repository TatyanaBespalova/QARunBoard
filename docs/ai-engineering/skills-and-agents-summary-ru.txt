КАК МЫ ОРГАНИЗОВАЛИ РАБОТУ СО СКИЛЛАМИ И АГЕНТАМИ

Скилл — процедура: определяет порядок выполнения задачи и проверки результата.

Агент — исполнитель: выполняет задачу в рамках своей роли, полномочий и ограничений.

1. ПРАВИЛА СОЗДАНИЯ

Для каждого скилла и агента мы определяли назначение, границы ответственности, ограничения и ожидаемый результат.

Общие требования закрепляли в AGENTS.md, процессы — в скиллах, обязанности исполнителей — в конфигурациях агентов.

Создали два скилла: implement-feature для реализации и review-and-validate для проверки. Работу разделили между агентами code_writer и code_reviewer.

2. ОГРАНИЧЕНИЯ

- Сначала изучить существующий код, затем вносить изменения.
- Выполнять только согласованную задачу, не переписывать несвязанный код.
- Не придумывать требования: существенную неоднозначность уточнять у пользователя.
- Не добавлять зависимости без необходимости.
- Не подавлять ошибки TypeScript и lint, не ослаблять тесты ради успешной проверки.

3. БЕЗОПАСНОСТЬ

- Сохранять чужие незавершённые изменения.
- Не выполнять staging, commit и push без явного разрешения.
- Не размещать секреты и токены в клиентском коде.
- Проверять внешние данные и не ослаблять защитные настройки.
- Ограничить ревьюера режимом только для чтения: он сообщает о проблемах, но не изменяет код.

4. КОНТРОЛЬ КАЧЕСТВА

Для реализации требовали применимые тесты, lint, сборку, просмотр изменений и проверку интерфейса в браузере при изменении UI.

Затем результат передавался независимому ревьюеру. Каждое замечание должно опираться на доказательства; предположения и необязательные улучшения отделяются от дефектов.

Дефекты уровня Critical, High и Medium запускают цикл: исправление → повторные проверки → повторное ревью.

5. КОНТРОЛЬ САМИХ ИНСТРУКЦИЙ

Скиллы и инструкции агентов уточняли на основе выявленных проблем: ограничивали объём изменений, усиливали правила уточнения требований и обоснования замечаний.

Отдельные автоматические тесты для скиллов в репозитории не зафиксированы. Контроль строился на анализе инструкций и результатов их применения.

Критерий завершения: требования выполнены, необходимые проверки пройдены, независимое ревью завершено. Пробелы в проверке и оставшиеся риски сообщаются явно.
